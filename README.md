# Eldevo Publish · إلديفو

منصة عربية RTL تربط أصحاب التطبيقات بأصحاب حسابات Google Play، مع طلبات وعروض ومحفظة وإدارة شاملة.

## ما بُني

- تسجيل منفصل لصاحب التطبيق وصاحب حساب النشر؛ دخول مستمر، كلمات مرور scrypt، جلسات HttpOnly، حماية CSRF، تحديد المحاولات واستعادة كلمة المرور عبر البريد عند إعداد المزود.
- تطبيقات خاصة ورفع AAB/APK، فحص بشري موثق، سوق للناشرين المعتمدين، عروض، اختيار ناشر، محادثات، تسليم، اعتراض وتسوية، تجديد وتحديثات.
- ميزانية يحددها صاحب التطبيق؛ حد أدنى 50$ وعمولة 20% افتراضيًا. رسم فحص 10$. جميع القيم قابلة للتعديل، ويحفظ الطلب لقطة الأسعار.
- صفحة دفع بتصميم الموقع، تحتوي حقول الدفع الآمنة من **Whop Embedded Checkout**. لا انتقال إجباري لصفحة Whop العامة، باستثناء إجراءات المصادقة التي قد تطلبها وسيلة الدفع.
- إنشاء جلسات بسعر خادمي وإضافة الرصيد حصريًا بعد webhook موقّع مطابق للمبلغ والعملة والعميل والخطة. منع الائتمان المكرر. إشعارات الاسترداد/النزاع تجمّد حساب الدافع وتحتاج مراجعة محاسبية.
- سحب أرباح الناشر عبر USDT/TRC20 أو USDC/Polygon. حد أدنى 25$ ورسوم ثابتة 2$ افتراضيًا مع نسبة اختيارية. حجز، صافي معروض، وموافقة إدارة بعد **تنفيذ التحويل فعليًا خارج الموقع** وتسجيل TxID والكمية. لا مفاتيح محافظ ولا تحويلات blockchain آلية.
- لوحة إدارة: المستخدمون، الناشرون، التطبيقات والفحص، الطلبات، المدفوعات، السحب، النزاعات، التحديثات، الدعم، الإعدادات وسجل تدقيق.
- تحقق من صفحات Google Play العامة **بدون Google Play API**. رمز في وصف التطبيق المنظم، مطابقة الرابط الأساسي وURL هوية الناشر. حالات غير حاسمة لا تصرف الأموال. التحقق لا يثبت الملكية القانونية أو تطابق الملف المنشور.

## التشغيل

يتطلب **Node.js 24+** وقرصًا دائمًا لقاعدة SQLite والملفات. لا يحتاج خادم قاعدة بيانات منفصل.

```bash
npm ci
cp .env.example .env
npm run dev
```

واجهة التطوير: `http://localhost:5173`، الخادم: `http://localhost:3000`.

للإنتاج:

```bash
npm run build
npm start
```

اضبط `APP_ORIGIN` على الدومين النهائي، و`NODE_ENV=production` مع HTTPS، و`HOST=0.0.0.0` عند استخدام حاوية. **لا تستخدم هذا الإصدار على نظام ملفات مؤقت مثل Vercel Serverless**؛ استخدم Docker/VPS أو خدمة Node بقرص دائم. لا تضع مجلد `data` داخل مجلد الويب العام.

## إنشاء المدير

لا توجد بيانات دخول افتراضية، ولا يمكن تسجيل مدير من الواجهة. ضع `ADMIN_EMAIL` و`ADMIN_PASSWORD` (14 حرفًا على الأقل) في بيئة الخادم ثم شغّل:

```bash
npm run admin
```

يمكن استخدام الأمر نفسه لاستعادة حساب المدير. احذف متغير كلمة المرور من البيئة بعد التنفيذ. صفحة الإدارة `/admin`.

## Whop

أضف من حسابك: `WHOP_API_KEY`, `WHOP_COMPANY_ID`, `WHOP_PRODUCT_ID`, `WHOP_WEBHOOK_SECRET`.

- ضع webhook على `https://YOUR_DOMAIN/api/webhooks/whop`.
- فعّل `payment.succeeded` وأحداث refund/dispute المتاحة في إصدار حسابك.
- صلاحيات إنشاء checkout configurations والخطط وقراءة/استقبال بيانات المدفوعات مطلوبة حسب وثائق Whop.
- تحقق من أن حسابك ومنتجك يدعمان نموذج الخدمات/المنصة قبل استقبال مدفوعات حقيقية.
- نفذ دفعة اختبار فعلية واختبر توقيع webhook وsubtotal وmetadata والاسترداد. هذا المستودع لا يحتوي مفاتيح ولا يسجل نجاح دفع تجريبي على أنه حقيقي.
- زر نجاح المكوّن أو رابط العودة لا يزيد الرصيد؛ الزيادة تأتي فقط من webhook.
- الـ checkout هو تصميم إلديفو المحيط بمكوّن Whop؛ لا نعيد تصميم حقول البطاقة خارج مزود الدفع.
- رسوم Whop ليست مضمّنة في عمولة المنصة المحاسبية؛ يعرض مزود الدفع أي رسوم أو ضرائب يطلبها، وتحتاج الإدارة مطابقة صافي التحصيل.

المراجع التي بُني عليها التكامل:
[Embedded Checkout](https://docs.whop.com/payments/checkout-embed)، [Checkout configurations](https://docs.whop.com/api-reference/checkout-configurations/create-checkout-configuration)، [Webhooks](https://docs.whop.com/developer/guides/webhooks).

## البريد

اختياري: `EMAIL_WEBHOOK_URL` لخدمة بريد HTTPS تملكها و`EMAIL_WEBHOOK_TOKEN`.
يرسل الخادم JSON `{to, subject, text}` مع Bearer token. دون مزود، تظهر رسالة واضحة أن الاستعادة بالبريد غير مفعّلة. لا تظهر رموز الاستعادة في المتصفح أو السجلات.

## النسخ الاحتياطي والقيود

- جميع البيانات والملفات داخل `DATA_DIR` (افتراضيًا `./data`). انسخ SQLite بواسطة backup API أو بعد إيقاف الخادم، مع مجلد uploads؛ لا تنسخ ملف SQLite الجاري وحده متجاهلًا WAL.
- فحص التطبيق بشري؛ التحقق من امتداد الملف وبصمته **ليس فحصًا للبرمجيات الخبيثة**. يلزم مسار فحص معزول قبل الموافقة على ملفات العملاء.
- السحب يظل pending حتى تنفذ الإدارة التحويل وتسجل معرّفه. تسجيله ليس تحققًا تلقائيًا من blockchain.
- أوقف تسوية أي حساب مرتبط بنزاع دفع إلى أن تتم مطابقة الأموال؛ الإرجاع إلى المحفظة يختلف عن الاسترداد إلى البطاقة.
- التحقق العام حساس لتغييرات HTML وحجب Google واختلاف الدول. يتوقف بأمان عند عدم وجود دليل كافٍ. اختبره على حساب ناشر حقيقي قبل الاعتماد التجاري.
- الصفحات القانونية نصوص تشغيل أولية؛ أضف هوية الجهة المشغلة ووسائل التواصل والسياسات المعتمدة قبل إطلاق عام مدفوع.
- لا توجد بيانات مستخدمين وهمية أو أرصدة مجانية في التشغيل العادي. بيانات fixtures تُنشأ فقط في قواعد مؤقتة ضمن الاختبارات.
